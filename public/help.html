1. 三分钟看懂：它是做什么的

普通 AI 聊天应用只有「一双手」——能干活，但干完就完，工具永远不变。Dual-Agent 有两层大脑：

  • 内层执行 Agent（左中栏）：接到你的任务后自主规划，调用插件干活——写文件、跑命令、查资料、记笔记，循环往复直到完成。
  • 外层评审 Agent（右栏）：像一个随身架构师，定期阅读内层的工作日志与插件源码，提出「改进建议」（新增/修改/删除插件），经你审批后热加载生效。

于是系统在使用过程中越用越顺手：内层暴露出的弱点（某个插件不好用、某类任务缺工具），会被外层发现并修复，全程你只需要点「批准」。

3. 内层执行 Agent：任务是怎么完成的

你的任务如「把 test.pdf 转成 markdown」
↓
内层 LLM 规划系统提示 + 记忆检索 + 技能清单
↓
调插件write/read/bash…
→
拿结果全文回填对话
→
再规划下一步或收尾
↑ 循环（同轮最多 24 轮，单插件连续失败 3 次自动止损）
↓
最终中文总结产出文件路径 + 关键结果

执行前的固定动作

  • 记忆检索：先 memory.search(任务关键词)，历史偏好/项目结构作为背景。
  • 技能扫描：skill.list() 只载入名称+描述（约 100 token/技能，省上下文）；发现相关技能必须 skill.get() 读全文并照步骤执行。

执行中的保护

  • 参数净化：模型流式输出的参数偶有残缺（键无引号/截断/丢失），框架自动修复或给出精准重试提示，避免死循环。
  • 止损：同一插件连续失败 3 次即跳过，强制换策略。
  • 传输降级：参数连续 2 次在传输中丢失，自动提示改「分段写入」模式。
  • 上下文预算：会话超过 6 万字符时，旧工具结果自动折叠（保留首尾），永不撞 token 上限；完整过程仍落盘 process 页。

4. 外层评审 Agent：系统是怎么自我改进的

① 触发评审右栏对话 / 插件页「AI 修复」
低质量插件自动标记
→
② 注入上下文插件清单+源码+失败日志
+质量记分+审批历史
→
③ 产出建议标准 JSON（create/update/delete）
↓
④ 审批栏（你决定）代码 diff 预览 · 危险模式警告 · 批准 / 拒绝
↓ 批准后
⑤ 快照改动前插件备份
→
⑥ 预检闸门结构冒烟+全量回归
→
⑦ 热加载立即生效无需重启
↓ 若出问题
一键回滚恢复到最近快照（回滚本身也可回滚）

外层每条建议都带 reason（改什么、为什么）。被拒建议进入审计历史，评审提示会附上最近决定，避免反复提同一提案。

预检闸门（v0.8.0+，坏插件进不了运行时）

  • 阶段一 结构冒烟：沙盒加载插件代码——语法错误、缺少 params 定义、run 非函数、引用第三方模块（本项目零依赖）直接拦截。
  • 阶段二 全量回归：把「待审变更 + 现役全部插件」复制进隔离沙盒，完整跑一遍 smoke 测试；破坏其他插件依赖的改动被拦截。

插件质量记分

每次评审自动附带各插件的失败率统计；近期调用 ≥5 次且成功率低于 60% 的插件被标记 低质量，外层会优先诊断它。

5. 插件系统（工具层）

插件职责要点
bash 基础执行 shell 命令超时保护；无输出的重定向给确认提示
write 基础写文件原子写入（tmp+rename）；append 幂等（重试自动去重）；高相似续写拦截 / 低相似重构放行
read 基础读文件offset/limit 分段、tail 读尾；skill: 协议直读技能捆绑资源
edit 基础精确替换oldText 必须与文件完全一致
fetch 联网抓网页正文导航/菜单/页脚去噪；title 置顶；正文截断保护
search 联网搜索多引擎；结果配合 fetch 读全文
memory 基础三层记忆TF-IDF 检索；consolidate 归并
skill 技能技能库Agent Skills 开放标准；GitHub 一键安装
todo 规划任务清单多任务并行勾选

插件是原子级单一职责的 JS 文件（plugins/<name>.js）：文件头 // @name // @desc // @essential 提供元信息，导出 params（JSON Schema，模型据此填参）与 run(args, ctx)。左栏插件页可直接在线编辑，保存走同一审批管线（快照+预检+热加载）。

6. 技能系统（方法论层）

插件是「手」，技能是「操作手册」。技能 = 一个 markdown 文档（含步骤），兼容 Agent Skills 开放标准，社区技能零适配直接用。

渐进式三阶段
list 名称+描述（~100 token/技能）
→
get 全文
SKILL.md + 捆绑资源清单
（skill: 路径 + bash 绝对路径）
→
按需取资源
read 用 skill: 协议
bash 用清单里的绝对路径
  • 两个搜索根：工作区 skills/（就近优先）+ 项目根 skills/（全局共享）。同名技能工作区版本覆盖全局。
  • 目录型标准技能：<name>/SKILL.md（YAML frontmatter：name + description）可捆绑 scripts/references/assets；单文件简化格式：<name>.md。frontmatter 支持多行 YAML。
  • 一键安装：对话里说「安装 owner/repo 的 xx 技能」即可——框架从 GitHub 拉 tarball、内存解包、自动发现技能目录、记录版本（skills/.installed.json）。支持仓库简写 / 子目录 / 完整 URL，仓库级批量安装。
  • 沉淀：内层完成复杂任务后可用 skill.save() 把方法存为新技能，下次直接复用。

7. 记忆系统

层级存续存什么容量
session当前会话对话上下文（框架自动管理）受上下文预算保护
short（近期）持久化任务摘要（≤500 字）滚动 20 条
long（长期）持久化用户偏好、项目结构、技术选型（≤1000 字）滚动 20 条
  • TF-IDF 检索：中英混合分词（英文按词 + 中文二元组），相关度排序——比子串匹配召回更准，「界面主题」能同时召回「主题色改蓝紫」和「深色主题界面」。
  • consolidate 归并：memory(action="consolidate") 把同主题的近期记忆簇归并成一条长期记忆（保留全部要点），释放近期容量——避免同任务的多条过程记忆被新任务挤出。
  • 防重：保存前精确去重；保存的 id 单调递增，删除不回退。

记忆随工作区隔离：切换工作区后互不干扰（会话、技能、过程文件同理）。

8. 安全与质量闸门

机制作用
审批制外层建议只有你批准才生效；危险模式（child_process、网络、eval…）在审批时黄条警告
静态 lint语法错误的代码连审批队列都进不了
预检闸门批准后先过沙盒冒烟 + 全量回归，坏插件进不了运行时
快照回滚每次改动前自动备份（保留最近 2 版）；插件页「回滚」一键恢复，回滚本身可再回滚
审计日志全部关键操作（提案/批准/拒绝/回滚/拦截）带时间戳落盘，页面右上角可查
止损同插件连续失败 3 次即停，防模型在错误上无限重试烧 token

9. 健壮性机制（自动恢复）

故障自动处理
LLM 限流（429/配额/过载）指数退避重试：3s → 9s → 27s → 81s，共 4 次；界面上可见「⏳ X 秒后自动重试（第 n/4 次）」
网络抖动（连接重置等）同上序列自动重试
非限流错误（400 参数错等）立即失败——不掩盖真实配置问题
流式参数残缺自动净化（补引号/合桶）；整体丢失给精准重试提示；连续丢失强制分段模式
会话过长上下文预算自动折叠旧工具结果（落盘完整，发送压缩）
页面刷新/误关正在执行的任务不受影响；重开页面自动恢复锁定状态并轮询至完成
服务重启待审批队列、会话、记忆、审计全部持久化，重启即恢复

变量默认说明

DUAL_AGENT_MOCK=1-演示模式（无需真实 API）
DUAL_AGENT_AUTO_APPROVE=0开关闭外层 opencode --auto（可能因权限询问卡住）

部署：node server.js 即可（Node ≥18，无任何 npm 依赖）。配置内层 API：右上角「配置」填 base_url / api_key / model（OpenAI 兼容接口）。

12. 常见问题 FAQ

Q：内层一直显示「执行中」没有输出？

任务可能处于工具调用阶段（如跑长命令）。看中栏状态条当前插件，双击打开 /process 看实时日志。若触发限流会显示 ⏳ 自动重试倒计时。

Q：外层提的建议被「预检拦截」了？

预检发现该建议代码有结构问题（语法/缺 params/引第三方模块）或会让全量回归测试失败。拦截详情在审计日志；让外层「看预检错误重新修复」即可。

Q：插件改坏了怎么办？

左栏插件页「回滚」一键恢复最近快照；连续回滚在两个版本间交替。

Q：怎么装社区技能？

直接对话：「安装 anthropics/skills 里的 docx 技能」。或手动把技能目录拷进 skills/，刷新即可发现。

Q：多个项目怎么互不干扰？

中栏顶部切换工作区：会话、记忆、技能、过程文件按工作区隔离；插件全局共享。
